# Contributing

Thank you for looking. This is a small export from a private product, so the rules are short.

## Right now: issues only

- Open an issue using the "Bug" or "Docs fix" form. Problems in the files under `examples/` (a command that fails, a wrong setting, an outdated image tag) are reported the same way: name the example folder, your operating system and Docker version, and the exact command and error. Do not paste your `.env`.
- Outside pull requests are disabled for now. Please do not open them.
- Issue replies are best-effort; no response time is promised.
- Do not put secrets, personal data or customer data in an issue. Security problems go to `SECURITY.md`, not to a public issue.

## When pull requests reopen

This file will be updated first. The rules will then be:

- Sign off every commit with the Developer Certificate of Origin: `git commit -s`. This adds a `Signed-off-by:` line and means you agree to the DCO 1.1 (https://developercertificate.org/).
- Your contribution is licensed under the licence of the directory you change, as listed in `LICENSES.md`: CC BY 4.0 for documentation, Apache-2.0 for code and configuration, including the files under `examples/`.
- Fonts and brand assets are not accepted as contributions.
- Keep changes small and in the existing style.

## Docs corrections sent as issues

If you describe a correction in an issue (a corrected sentence, command or paragraph) and the maintainer uses it, you agree that the text you wrote is offered under CC BY 4.0, the same as the documentation. Only send text you wrote yourself or that you may share.

## Conduct

Be kind and be plain. See `CODE_OF_CONDUCT.md`.
